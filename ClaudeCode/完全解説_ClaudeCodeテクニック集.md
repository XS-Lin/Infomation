### コンテキスト汚染の典型パターン ###

|汚染パターン|原因|影響|
|---|---|---|
|タスク混在|異なるタスクの情報が混ざる|無関係な情報に引きずらた判断|
|失敗履歴直積|試行錯誤の結果が残る|同じ失敗パターンの繰り返し|
|過剰な探索結果|広範囲なコード検索の結果|重要な情報が埋もれる|
|古い状態の保持|修正前のコード状態が残る|修正済みの問題を再度指摘|

### /compactの使用例 ###

|コマンド|効果|
|---|---|
|/compact|デフォルト圧縮を実行|
|/compact APIの変更に集中して|API関連の情報を優先して保持|
|/compact テスト結果だけ残して|テスト結果を優先して保持|
|/compact エラーの原因に関する情報を保持|デバック情報を優先して保持|

### コンテキストウィンドウの比喩 ###

**コンテキストウィンドウは「作業机」である**

机の上に大量のファイルを開いて作業すると、すべてを一覧できますが、必要な書類を見つけるのに手間取り、うっかり別の書類を参照してしまうこともあります。

- /clear -> すべてを片付ける。
- /compact -> 要約したメモを残って書類をしまう。要約のため、細部は失われる可能性がある。

### 検証の手段の比較 ###

LLMに出力が正しくない可能性があるため

|検証手段|検出できる問題|コスト|適用場面|
|---|---|---|---|
|テストスイート|ロジックの誤り、リグレッション|中|全般|
|型チェック|型の不整合、インターフェース違反|低|静的型付き言語|
|リンター|コード品質、規約違反|低|全般|
|Bash実行|実行時エラー、出力の不正|低|スクリプト、CLI|
|スクリーンショット|表示崩れ、UI不具合|低|フロントエンド|

### ルール注入手段の比較 ###

|手段|注入タイミング|セッション後半での有効性|用途|
|---|---|---|---|
|CLAUDE.md|セッション開始時(ユーザーメッセージ)|減衰する|プロジェクトの概要、初期手段|
|claude/rules/(条件付き)|該当ファイルを初めて扱った時点|注入が新しいため有効|コーディングルール、テスト方針|
|--append-system-prompt|System Prompt追記|常時一定強度|CI/CDでの絶対的なルール|

### maxTurns設定の目安 ###

**サブエージェントは独立したコンテキストで動作するため、何らかの理由で処理が終了しない場合があるため、maxTurnsでサブエージェント実行できるターン数（ツール呼出す回数）を制限する**

|タスク種類|推奨maxTurns|理由|
|---|---|---|
|簡易チェック|5-10|数ファイルの確認のみ|
|コードレビュー|15-25|複数ファイルの読込と分析|
|テスト実行|20-30|テスト実行と結果分析|
|コードベース調査|30-50|広範なファイル走査|

### 実践的なHook例 ###

1. 機密ファイル保護フック

CLAUDE.mdに記載してもLLMの判断次第では無視されるリスクがある。

~~~json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read|Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/protect-secrets.sh"
          }
        ]
      }
    ]
  }
}
~~~

protect-secrets.sh

~~~bash
#!/bin/bash

HOOK_INPUT=$(cat)
TOOL_INPUT=$(echo "$HOOK_INPUT" | jq -c '.tool_input')

PROTECTED_PATTERNS=(
  ".env"
  ".env.local"
  ".env.production"
  "credentials.json"
  "secrets.yml"
  "id_rsa"
  ".pem"
)

for parttern in "${PROTECTED_PATTERNS[@]}"; do
  if echo "$TOOL_INPUT" | grep -qF "$pattern"; then
    cat <<ENDJSON
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Access to $pattern is blocked by security policy"
  }
}
ENDJSON
    exit 0
  fi
done
~~~

## 第７章 Tasksシステムとプロジェクト管理 ##

### 使い方 ###

Tasksシステムは特別なインストールや有効化の操作は不要で、Claude Codeに組み込まれている。

  - `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

    - セッション間共有
    - プロジェクトごとの分離

- /tasks
- Claudeに指示「すべてのタスクを表示して」

### マルチセッション共有 ###

~~~bash
# ターミナルタブ1
CLAUDE_CODE_TASK_LIST_ID=my-project claude

# ターミナルタブ2: 同じタスクリスト共有
CLAUDE_CODE_TASK_LIST_ID=my-project claude

# ターミナルタブ3: 同じタスクリスト共有
CLAUDE_CODE_TASK_LIST_ID=my-project claude
~~~

|注意点|詳細|対策|
|---|---|---|
|同一タスクの重複作業|ふたつのセッションが同じタスク着手|着手前にTastGetで確認|
|ファイルの競合|同じファイルを複数セッションが編集|タスクごとに対象ファイルを分離|
|依存タスクの早期着手|ブロック中のタスクに無理に着手|ステータスを必ず確認|
|ステータスの不整合|更新タイミングのずれ|TaskListで定期的に同期確認|

### Adaptive Thinking と推論制御 ###

リクエストの複雑さによってClaudeが「いつ、どの程度深く思考するか」を動的に判断する仕組み。

※本はOpus4.6の説明だが、正確にはドキュメント参照[Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)

### Thinking and effort ###

The thinking parameter controls whether Claude thinks in thinking blocks before answering; the effort parameter controls how much work Claude puts into the whole response, which in adaptive mode includes how often and how deeply it thinks.

※ [Thinking and effort](https://platform.claude.com/docs/en/build-with-claude/thinking#thinking-and-effort)

### 推論制御 ###

|シナリオ|推奨設定|理由|
|---|---|---|
|typo修正、変数名変更|努力レベルlow|深い推論が不要な単純作業|
|テストコード追加|努力レベルmedium|パターンベースの生成は十分|
|APIエンドポイントの実装|努力レベルmedium|既存パターンに沿った作業|
|バグの根本原因分析|努力レベルhigh|複数の仮説を検討するがある|
|アーキテクチャの設計|opusplan|計画にOpusの推論力を活用|
|大規模リファクタリング|努力レベルhigh|影響範囲の正確な把握が必要|
|Agent Teamsでの協調作業|努力レベルhigh|各エージェントの自律判断の質を最大化|

### モデル選択指針 ###

|モデル|適したタスク|コスト|推論能力|
|---|---|---|---|
|Opus|複雑な設計判断、大規模リファクタリング|高|最高|
|Sonnet|一般的な実装、バグ修正、テスト作業|中|高|
|Haiku|単純な修正、フォーマット、定型作業|低|標準|

### デバッグテクニック ###

- 詳細ログ ( claude --verbose )
  - APIリクエストに含まれるトークン数の内訳
  - プロンプトキャッシュのヒット状況
  - ツール呼出しの入出力の詳細
  - レイテンシーの計測結果
- ログ保存先(~/.claude/、 ~/.claude/projects/)

### トラブルシューティング早見表 ###

|問題|最初に確認すべきこと|即効性のある対策|
|---|---|---|
|応答が遅い|キャッシュヒット率|CLAUDE.mdの変更を控える|
|応答品質低下|コンテキスト使用率|/compactまたは/clear|
|MCPツールが使えない|setting.jsonの構文|jqでセッション構文検証|
|Hookが動かない|スクリプトの終了コード|手動でスクリプトを実行|
|パーミッションエラー|ファイルの権限設定|permission.allowに追加|
|コストが想定以上|予算とモデル選択|--max-budget-usdを設定|
|メモリー消費の増大|プロセスのRSS|Ctrl+cで終了して再起動|
